WHAT IS GENUINELY WELL-BUILT (verified, not assumed):
  * TTYD URL host is DERIVED live from `hostname -I`, preferring the LAN IP and
    skipping docker bridges (172.x) and loopback. Not hardcoded.
  * Each ttyd runs as a child of nexus.service, does `docker exec -it <container> sh`
    into the REAL container, `-W` writable. ttyd sends no X-Frame-Options/CSP, so
    the cross-origin iframe embedding works. Verified: iframe LOADED ok.
  * Teardown is clean: stop 200 -> containers 0, ttyd 0, session gone.

DEFECT FOUND:
  start_ttyd_process bound ttyd with `-i 0.0.0.0` while ADVERTISING the LAN IP in
  the URL. So the bound interface and the URL disagreed: a student's live,
  WRITABLE root shell in their lab container was reachable from ANY host on the
  network (any routable interface), not only the LAN address the UI points at.
  There is no auth on ttyd. On a demo LAN this is likely intended-ish, but it is
  wider than the advertised contract and it was not a deliberate-looking choice -
  the hardcoded 0.0.0.0 sat right next to code that carefully derived the host.

FIXED (reversible): hoisted host detection into `_detect_ttyd_host()` and used it
  for BOTH the bind and the advertised URL, so they cannot disagree. Falls back to
  0.0.0.0 only when detection yields nothing. Backup:
  backend/main.py.bak-2026-09-28-ttydbind
