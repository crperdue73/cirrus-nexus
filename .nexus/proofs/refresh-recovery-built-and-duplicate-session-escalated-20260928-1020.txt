REAL DEFECT (student-facing, in-scope):
  A student who starts a lab and REFRESHES the page cannot get their terminals
  back. loadLabs() returns them to the catalog; loadLiveSessions() shows their
  running lab with ONLY a Stop button. There is no reattach path:
    `currentSession` is only ever set from a start response.
  Worse: pressing Start again on the same lab creates a SECOND full session -
  measured live: 6 containers + 6 ttyd from one student's two starts
  (53060ea6 and 2c08507b, same lab_id, both "running"). Nothing reclaims the
  orphaned set. On demo day this doubles the host's container load per refresher
  and can exhaust the ttyd port pool.

FIXED (frontend + a small additive backend field; reversible):
  1. main.py: the session dict now retains the node->ttyd map (it previously kept
     only a flat ttyd_ports list and threw the map away after the start response),
     and GET /api/sessions now includes it per session.
  2. index.html: the running-sessions list shows a "Reconnect" button for any
     session that has terminals; new reconnectSession(sid) rebuilds the terminal
     view against the EXISTING session (fetch sessions -> find entry -> fetch labs
     -> getSessionHTML + iframes). It never starts a new session. Errors render an
     honest "Could not reconnect" panel.
  Backups: backend/main.py.bak-2026-09-28-reattach
