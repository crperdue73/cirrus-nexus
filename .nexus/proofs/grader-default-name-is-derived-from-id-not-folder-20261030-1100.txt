  ADDING-A-LAB.md said: "`grader` defaults to `grader_<id>` when omitted".
  backend/main.py:497 (read, live) sets grader_module = meta.get("grader", f"grader_{lab_id}")
  and lab_id is metadata.id. Both shipping ids are sentences:
    demo-01-two-pcs-and-a-real-switch-unsolved -> default grader_demo-01-two-pcs-and-a-real-switch-unsolved
    demo-02-two-switches-one-router-unsolved   -> default grader_demo-02-two-switches-one-router-unsolved
  _load_grader (main.py:751-793) resolves only <name>.py under LABS_DIR or backend/graders/.
  Neither default file exists. So a lab that omits `grader:` gets NO grader and falls through to
  _fallback_grade (main.py:1647-1650) -- an IP/ping check -- silently. The doc's "always ship it
  explicitly" advice was right for the wrong reason: it read as house style, not as "the default is dead."
