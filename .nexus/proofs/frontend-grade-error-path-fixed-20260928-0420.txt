WHY: 32 runs tested the API server-side. Nobody had tested what a STUDENT SEES
when something fails - the frontend's error paths. Read every async fetch handler.

WHAT'S ALREADY GOOD: startLab guards !resp.ok and surfaces the SERVER's detail
('Lab not found'), escaped via escapeHtml. submitGrade handles 409 refusal as its
own state, and grader status 'error' is never rendered as "Not yet". Honest design.

DEFECT FOUND (student-facing, in-scope):
  submitGrade is the ONLY handler that indexes into the response (data.grade),
  and it had NO try/catch and NO general !resp.ok guard. Consequences:
   - a rejected fetch (network drop, or the server restarting - nexus.service has
     RestartSec=10, proven live in run 25) left "Grading..." spinning FOREVER;
   - any non-OK JSON body (400/404/500 with a `detail`) fell through to
     `data.grade`, then `grade.passed` -> TypeError, no verdict shown.
  The other handlers that read a response all guard against this. This one did not.
