--- DEFECT 1: grader_demo_02.py graded FAKE-SWITCH labs as PASSED ---------
Symptom (LIVE, cold deploy, 5/5 nodes up):
  session with sw1 := an alpine PC, sw2 := sw1 (a real switch):
    per-node sw1 -> passed=False  ("sr_cli not available — not an SR Linux switch")
    per-node sw2 -> passed=False
    but grade_all() -> passed=True   <-- HOLE
Cause: grade_all() only computed
    e2e = results["pc-a"]["passed"] AND results["pc-b"]["passed"]
  It NEVER consulted the sw1/sw2 real-switch checks. So the LAB verdict was
  satisfiable by a Linux PC bridge answering pings — exactly what Dad ruled out.
Compare: grader_demo_01_srl.grade_all() DID require results["sw1"]["passed"].
  demo_02 simply dropped it.

FIX (lab-definitions/grader_demo_02.py, grade_all):
    real_switches = results["sw1"]["passed"] and results["sw2"]["passed"]
    router_ok     = results["r1"]["passed"]
    lab_passed    = e2e and real_switches and router_ok

RE-VERIFIED LIVE against the same cold deploy:
    REAL switches  -> lab passed: True   (expect True)
    FAKE sw1/sw2   -> lab passed: False  (expect False)
      sw1: "sr_cli not available — node is not an SR Linux switch"
      sw2: "10.0.2.254 not found on irb0.0"

--- DEFECT 2: grader_demo_01_cumulus.py had NO grade_all() ---------------
  Every sibling grader defines grade_all(); the Cumulus grader did not.
  A lab-level verdict contract that only this lab lacks = the Cumulus lab
  could not enforce the real-switch requirement at the LAB level.
FIX: added grade_all() requiring
    lab_passed = results["pc-a"]["passed"] and results["sw1"]["passed"]
  (same contract as grader_demo_01_srl). Added __main__ entry too.
