Date: 2026-09-28 ~17:20 EDT   By: Selina   Trigger: cron run 46

TRIGGER: run 28 found installer-vs-live unit divergence (aegis.service vs
nexus.service, User=aegis vs student) but never evaluated CORRECTNESS. This run
read both units and verified them with systemd itself.

DEFECT 1 (installer, real): install.sh generated `Requires=docker.service`.
  systemd.unit(5): Requires= "declares that if the unit bound to is stopped, this
  unit will be stopped too". docker.service on this host is Restart=always and the
  journal shows ~30 start/stop events in the last 200 lines - it DOES restart.
  So the installer's unit would tear down AEGIS (and every running lab) every time
  docker restarts. The live unit used Wants=, and nothing documented why.
  FIXED (reversible): the generated unit now uses
  `After=docker.service network-online.target` + `Wants=docker.service network-online.target`,
  with a comment explaining why Requires= is wrong here.
  Backup install.sh.bak-2026-09-28-requires-docker

DEFECT 2 (LIVE unit, real, pre-existing): nexus.service put
  `After=docker.service` and `Wants=docker.service` inside the [Service] section.
  systemd-analyze verify: "Unknown key 'After' in section [Service], ignoring." and
  the same for Wants. So the unit's own comment ("keep this unit from starting
  before they are up") asserted an ordering that DID NOT EXIST.
  MEASURED: `systemctl show nexus.service -p After | grep -c docker` = 0 before.
  Impact: on boot AEGIS could start BEFORE docker; a lab deploy at that moment
  would fail. A live product defect, not just a docs issue.
  FIXED (reversible): moved both keys into [Unit]. Verified: systemd-analyze verify
  clean; `docker now in effective After: 1`; daemon-reload OK; service active; /api 200.
  Backup: .nexus/nexus.service.bak-2026-09-28-unitfix
