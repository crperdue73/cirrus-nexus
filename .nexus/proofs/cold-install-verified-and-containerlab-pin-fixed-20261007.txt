BUG FOUND (the reason this test mattered)
  install.sh pinned containerlab 0.60.0. The lab topologies use `type: ixr-d2l`,
  which containerlab < 0.75 REJECTS:
      "failed to initialize node "sw1": wrong node type. 'ixr-d2l' doesn't exist."
  => a fresh install served the UI and the catalog but COULD NOT DEPLOY A LAB:
      POST /api/sessions/start returned HTTP 500.
  The development host runs containerlab 0.75.0 (accepts ixr-d2l), which is why the
  bug was invisible there and only appeared on a clean host.

FIX
  install.sh now pins containerlab 0.75.0 — the version the labs are authored and
  verified against. Re-tested in the same fresh container: session start returned
  200 and the 3 containers came up.

NOT EXERCISED
  The FRR BGP-variant substrate and any lab beyond the two shipping labs were not
  deployed. Lab-A was exercised end-to-end; Lab-B (the FRR router) builds and its
  image is present but was not deployed in this run.
