WHAT IS ACTUALLY TRUE (measured, reproducible):
  - A grader module is imported ONCE per server process and then held in
    _GRADER_CACHE. Grading a node returns the CACHED module.
  - So: edit lab-definitions/grader_*.py on disk + grade WITH the cache warm and
    NO reload -> the OLD score comes back, silently. Measured: injected score
    0.555, grade without reload returned 1.0 (stale); POST /api/labs/reload, grade
    again -> 0.555 (fresh); restore file + reload -> 1.0. Reproduced twice.
  - BUT a grader the process has NOT yet loaded is compiled fresh from disk on its
    first grade (measured: injected 0.123 before the lab had ever been graded in
    that process -> the very next grade returned 0.123 with no reload).
  - AND POST /api/labs/reload DOES clear the cache (backend/main.py:1304
    _GRADER_CACHE.clear()), and it works live -> {"status":"reloaded","count":16}.
  So the trap is: "an edit is invisible to a WARMED cache until reload or
  restart", NOT "an edit is never picked up".
